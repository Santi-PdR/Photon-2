## Original project and supplied artifact

The upstream Low-Drag-MC Photon project describes Photon as an in-game VFX toolkit/editor. Its documented systems include a Unity-style emitter/particle system, trails and beams, editor and timeline, shader graphs and post-processing, mesh/model particles, FX Packs, commands, and a Java integration API. The official `26.2` source branch (`8232cb4`, 2026-09-25) matches the supplied 26.2.2.3 artifact and is now the target behavior reference. The official `1.21` branch and the supplied artifact were also inspected.

The supplied `/home/Santipdr/Descargas/photon-neoforge-26.2-26.2.2.3.jar` is a Photon 26.2.2.3 NeoForge build for Minecraft 26.2, not a Forge 1.20.1 reference build. Its metadata requires NeoForge `[26.2,)`, Minecraft `[26.2, 26.2]`, LDLib2 `[26.2.2.41.a,)`, and KilaGraph `[26.2.0.15,)`. It declares Java 21 mixin compatibility, embeds KilaGraph 26.2.0.15, and its class files have bytecode major version 69 (Java 25). Inventory: 882 files (740 Photon classes, 135 assets, 52 shader files, 6 OBJ files); no `data/` entries, `.fx` projects, or `.fxpack` examples. 589 of the Photon classes are under `client/`; render, post-FX, FX runtime, and editor GUI dominate the remaining client tree. It declares a required Mixin plugin, client mixins, and access transformers for Minecraft and OpenGL/Iris internals. The artifact is useful for mapping the newer architecture and assets, but its target platform, Java bytecode, and dependencies do not match the requested target.

The largest Photon class groups in the supplied artifact are `client/gameobject` (311 classes), `client/render` (92), `client/postfx` (77), `gui/editor` (75), and `client/fx` (71). Packaged resource groups are 92 shader files (shader sources plus pipeline JSON), 35 PNGs, 6 primitive OBJ models, and two language files. There are no packaged sound files or data resources. This gives a concrete port inventory: the substantial work is client runtime/rendering/editor/shader code rather than blocks, items, or entities.

The local Forge baseline is a community Photon 2.2.6.a port, not an official 26.2 port and not the separate Photon 1.x project. Its provided LDLib2 2.2.39.a and KilaGraph 20.1.0.14 Forge 1.20.1 artifacts are now in `libs/`. The current source tree compiles under Java 17 with the declared Embeddium/Oculus APIs and Iris bridge included. Client/server runtime integration remains to be verified.

## Runtime behavior comparison

- Compared `FXObject`, `Emitter`, `ParticleEmitter`, `BeamEmitter`, and `TrailEmitter` against the official 26.2 source at `8232cb4`.
- `CustomShaderMaterial` now exposes `setUniformValue` and `getUniformValue` for user-defined shader uniforms, persists overrides in its additional NBT, and reapplies them to the selected shader variant without recompilation. Engine-owned `U_*` values remain controlled by the render pipeline. This builds and the client starts; a real material setter call and save/load round trip remain unverified.
- Compared all four client-bound command payloads with 26.2. Their encoded field order, optional resource-location markers, entity ID lists, and command argument behavior match; the Forge channel dispatch layer is the platform-specific adaptation and has not been exercised in multiplayer.
- The entity-effect command's auto-rotation argument and wire value are now a common `AutoRotateMode`; `EntityEffectExecutor.AutoRotate` remains as a client API bridge, preserving its enum order and existing constructor. Client packet work and FX resource suggestions execute only behind the physical-side gate. Bytecode inspection confirms the common argument class no longer references `EntityEffectExecutor`; a dedicated-server launch remains unverified.
- The shared tick/update and particle-emission sections in `FXObject`, `Emitter`, and `ParticleEmitter` remain present in the Forge sources. The direct differences in these files are Minecraft API substitutions (light lookup, particle render hooks, clamping) and renderer extraction/batching code replaced by the 1.20.1 `ParticleRenderType` / render-pass pipeline.
- `TimelinePlayer` retains the fractional-rate master clock and scales frame interpolation by the playback rate. Post-process clip submission is moved from the root object's frame callback into a pre-render preparation hook, deduplicated per render frame; both the custom particle manager and the vanilla render hook call it.
- Static and animated glTF sources now pass their resource identifier into the parser. Relative external buffer URIs resolve through the active Minecraft `ResourceManager`, remain inside the model's resource namespace, and are checked against their declared byte lengths. Sparse accessors now overlay validated, ordered sparse values over base or zero-initialized data for both float attributes and triangle indices, constrained to each declared buffer view. Java compilation and resource processing pass; importing representative external-buffer and sparse-accessor files in a client has not been exercised.
- This is source-level evidence for preservation of the inspected simulation path only. It does not establish equivalence for every particle type, timeline track, shader/material, or any visual runtime behavior. The renderer and timeline work remains partial and requires client verification.
